## Fixed rules (details and reasons are in DESIGN-CONTRACT.txt)

- One self-contained `index.html` (vanilla JS in a single IIFE, no framework) plus `sw.js` and `manifest.json`. State is saved only through `saveProgress()`/`loadProgress()` (localStorage key `japanSlowlyProgress_v1`, explicit fields only; bump the key if a saved field changes shape incompatibly).
- Look: semantic colour tokens in `:root` with light and dark values, accent `#E11401`, Outfit font, type scale 16px regular / 14px small / 12px bold uppercase labels (nothing smaller than 14px except labels), 24px side margins everywhere.
- The day card open/close (3D flip plus box-morph, `openDayFlip`/`closeDayFlip`) is a tuned, protected animation. `finishClose()` folds the landed card back into the deck instead of calling `render()`, and therefore has to mirror by hand what `render()` normally does (reload button, tab bar, `saveProgress()`, `updateStackClearance()`); the Stays slide-up (`openStay`/`closeStay`) has the same kind of bookkeeping. Any inline `style.transition` must be cleared afterwards. Read the contract before touching any of this.
- `render()` rebuilds `#screen` on every change and restores scroll and carousel position when the screen key is unchanged. It also calls `applyStatuses()` first, because day locks depend on progress in Guide Mode.
- Layout on phones: `#tabbar` lives in the persistent `#uiLayer`, sheets are absolutely positioned, plain CSS (no JS-measured positions, since round 25); pinch zoom is disabled in the viewport tag.
- One bottom-sheet component for About panels and stay chips (`sheetShell`, keys like `chapterId|a`, `chapterId|g1`, `stay|cN`), closed through `closeSheet()`, drag-to-dismiss wired in `wireSheetDrag()`.
- Photos are files in `cards images/` with pre-made locked variants (no runtime blur); a new photo must be added to `sw.js` `PRECACHE_URLS` and `CACHE_VERSION` bumped. `sw.js` serves HTML and the manifest network-first and images cache-first, and never touches the weather API.
- Content rules: no em dashes; no reservation numbers, pickup codes or card digits anywhere (the repo and page are public); teasers, not descriptions; day titles lowercase; content text never italic; Tomas (no accent); every locked card says exactly what to do to unlock; no red `timeNote` labels in newer days; guide-only material belongs in `GUIDE`.

## Chapter data cheat sheet

`DAY_DATA[n]` (Days 1-10, in code as `DAY1`..`DAY10`): `weather{lo,hi,cond,hourly}`, `energy`, `walking`, `outside`, `dress`, `bring`, `first`, `tomorrow`, `chapters[]`. A chapter: `id`, `name`, optional `kind:'essential'`, `startArrived`, `unlock` (what to do to open it), `expect` (how long), `gate:{time}`, `timeNote`; in the Info container: `hint`, `meta`, `booking`, `timing`, `checklist`, `bullets`, `maps`/`mapsUrl`; once unlocked: `blurb`, `bookingUnlocked`, `bulletsUnlocked`, `groups` or `about` + `aboutLabel`, `mapsUnlocked`, `readyLabel`. Stays: `STAYS` (id, label, areaName, range, unlockDay 1/4/5/8, mood, hotel, address) and `STAY_CARDS` (address, maps, chips, fields, lists); some stay chips read the About text of a day chapter by id (`kita-shinjuku`, `komanoyu`, `to-komanoyu`, `gion`, `yasaka-shrine`), so keep those ids. Day 11 is `{n:11, extra:true, ...}` in `DAYS`.
