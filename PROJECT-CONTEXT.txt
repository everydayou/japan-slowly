# Japan Slowly — Project Context

## Quick Status
Explorer Mode prototype is built and working: a draggable 10-day card-stack home screen, with Day 1 and Day 2 as fully clickable detail screens (open/close flip animation, progressive chapter reveal, weather-informed prep, PWA install support). It's a single self-contained `index.html`, no backend, no persistence, no real data feeds. Visual design runs on the same design-token architecture as the `leve` project (see round 2) — semantic color/font tokens with a light+dark remap, Outfit typeface, torii-red accent in place of leve's mint. **Live and installable on a real phone as of round 3**: hosted via GitHub Pages at `https://everydayou.github.io/japan-slowly/` (Settings → Pages → deploy from `main` / root), with the mobile-specific bugs that only showed up on a real device now fixed (see round 3) — a missing viewport tag, a touch-vs-drag conflict, and page-level scroll/bounce that shouldn't exist on this full-bleed app. Pushed to GitHub as of round 3 (2026-09-15). Guide Mode, Days 3–10, and the content-publishing pipeline are all unbuilt.

## How to Use This Document

## Design & Interaction Contract — fixed rules (read BEFORE touching UI/animation)
These were each arrived at after multiple rounds of iteration and user feedback. Don't change them without being explicitly asked to revisit them:
- **The home-reel drag zone needs `touch-action:none` on `.stack-wrap`, and `html`/`body` need to be locked from ever scrolling/bouncing** (round 3): a real phone was the only way this surfaced — desktop mouse/trackpad testing never showed it. With `touch-action:pan-y` (the original value) a real finger drag is never perfectly horizontal, so the browser's own vertical-pan gesture kept hijacking the custom drag as a native scroll/bounce, fighting the JS handler. Separately, `html`/`body` had no `overflow`/`overscroll-behavior` rules at all, so the whole document itself could pan and rubber-band in both directions even though `.screen` internally has `overflow:hidden`. Fixed with `touch-action:none` on `.stack-wrap`, `html,body{overflow:hidden;overscroll-behavior:none}` + `body{position:fixed;inset:0}`, and `overscroll-behavior:contain` on `.view` (the one element that's *supposed* to scroll, for a day's detail content). Don't reintroduce `pan-y` or drop the html/body lock without testing drag on an actual phone afterward — this class of bug doesn't show up any other way.
- **Design tokens are ported from the `leve` project's design system** (round 2): the `:root` block in `index.html` uses the same semantic roles leve uses (surface/content/border/accent, light+dark remap via `prefers-color-scheme` and a `data-theme` override) and the same Outfit typeface everywhere, replacing the original Fraunces/Work Sans/IBM Plex Mono mix. The one deliberate divergence: **the accent hue is a torii-red (`#d6432e` light / `#ff7a61` dark), not leve's mint** — chosen specifically to keep a Japan-flavored identity instead of reading as a re-skinned iOS app. Variable *names* (`--bg`, `--ink`, `--accent`, etc.) were kept unchanged from the pre-round-2 file so no other rule needed touching. Don't silently revert to the old warm/paper palette or reintroduce the three-font mix without being asked.
- **Card jitter range is 1–3°**, applied only to non-front deck cards (`CARD_JITTER` array in index.html). A wider 3–5° range was tried and explicitly rejected as "too much."
- **The front/focused card has NO tilt** (`rot:0` at offset 0). Adding one was tried, then explicitly reverted — it interacted badly with the deck-movement animation. Don't re-add without the user raising it again.
- **Open/close uses a combined 3D flip + FLIP-technique box-morph** (animating top/left/width/height, not `transform:scale`), specifically so photo/text proportions never distort. This is why the code reparents the card into `#screen` and manually computes pixel rects instead of using simpler CSS.
- **The rest of the deck gathers into a tidy, square, untilted stack while one card is open/closing**, then spreads back into its natural fan as the card lands. This exists specifically to mask the fact that a rotated card can't gracefully unrotate into a tilted slot on its own — it's a workaround, not a feature in its own right.
- **Card shadows fade via `box-shadow` transition only, never via opacity** — fading the whole card was tried and rejected ("makes the cards behind disappear").
- **The drag-release snap uses a gentle spring/overshoot curve** (`cubic-bezier(.34,1.56,.64,1)`, .6s — round 3), not a plain ease-out. The original curve decelerated almost immediately, so nearly all the motion happened in the first sliver of the transition and read as an abrupt snap regardless of duration; the spring curve settles slightly past rest before easing back, which reads as a natural physical "landing." This is specifically for the drag-to-browse release on the home reel — NOT the day open/close flip below, which is a separate, independently-tuned animation.
- **On close, the animated card element is folded directly into the deck as the permanent front card, not destroyed and rebuilt via a full `render()`.** This was a real bug (a one-frame subpixel "shimmer" from swapping a continuously-animated element for a freshly-laid-out one) — don't reintroduce a full-rebuild-on-close pattern.
- **The outer "gallery" demo chrome (title/description header, decorative side dots, phone-bezel mockup) has been removed.** The page is meant to be opened directly / installed as a home-screen app, so it should always just BE the app, full-bleed — don't reintroduce a phone-simulation wrapper.
- **A "jump" that looked like a real animation bug turned out to be a Safari-in-webview rendering quirk specific to the claude.ai chat's in-app preview** — confirmed fine in real Chrome and standalone Safari. If something like this comes up again, reproduce it in an actual browser (not the chat preview) before spending time on it. (Round 3 reinforces this: several real bugs — the touch-action conflict, the missing viewport tag — likewise only ever showed up on an actual phone, never in desktop testing. Always verify anything drag/touch/scroll-related on a real device before concluding it's fine.)
- **No real, named public figures or copyrighted film/show branding in any generated imagery** (a stylized "Lost in Translation" poster with Bill Murray/Scarlett Johansson was declined for Day 2; the user's own uploaded photo was used instead).

## What We're Building
Full product vision: see README.md (short) or `docs/Japan Slowly - Product Concept v2.docx` (full, includes its own zero-context Appendix A). One-line version: a spoiler-light PWA for a 3-person Japan trip (25 Sep–4 Oct 2026) where two travellers experience each day progressively instead of reading the full itinerary up front, while the planner has a separate operational Guide Mode.

## Current Scope (this prototype)
- Explorer Mode only. Guide Mode does not exist yet, not even a stub.
- Only Day 1 and Day 2 have real detail screens; Days 3–10 exist only as locked cards in the deck.
- All content (itinerary text, chapter data, "About this place" copy, weather numbers) is hardcoded in `index.html`. No API calls, no backend, nothing persists across a page reload.
- No automated tests. Verification so far has been manual/visual (Playwright screenshots + frame-by-frame video diffing during debugging, plus real-device testing on the user's phone starting round 3), not a real test suite.
- Live at `https://everydayou.github.io/japan-slowly/` via GitHub Pages (round 3) — can be installed to a phone home screen from there.

## Known Gaps
### HIGH
- None open.

### MED
- No persistence of chapter-reveal state (resets on every reload) — fine for a prototype, not fine for the real trip.
- No real weather API — prep cards show static demo numbers.

### LOW
- Front-card tilt was explicitly deferred (see contract above) — revisit only if asked.
- Accessibility is approximate: the close animation reuses a `<div>` (not a `<button>`) for the just-landed card, with `role="button"`/`tabindex` added as a stopgap rather than a real semantic fix.
- Paper-grain texture overlay (`--grain-opacity`) was left as-is over the new leve-derived neutral surfaces (round 2) — it read fine in light/dark screenshot checks against the new white/near-black backgrounds, but wasn't specifically re-tuned for them; revisit if it looks too subtle or too visible on a real device.
- `icon-512.png` and the manifest's icon references weren't regenerated to match the new red accent (round 2) — only `background_color`/`theme_color` in `manifest.json` were updated. Low priority since the app icon isn't part of the in-app UI.
- The new reload button (round 3, top-right of the home reel only) force-fetches the page via a cache-busting query string (`?v=<timestamp>`) rather than a real service-worker cache-invalidation strategy — fine for a single-file static prototype with no service worker, but worth revisiting if this ever grows a real offline/caching layer.
- The reload button is hidden on the day-detail screen (its fixed position would sit on top of the existing "Reset demo" button in that same corner) — it's only reachable from the home reel. Revisit placement if a reload-from-anywhere is wanted later.

### DONE (round 3)
- **GitHub Pages hosting turned on** (round 3): repo Settings → Pages → source = `main` branch / root. Live at `https://everydayou.github.io/japan-slowly/`, installable to a phone home screen from there (PWA meta/manifest were already in place from round 1).
- **Missing viewport meta tag fixed** (round 3): the file had no `<meta name="viewport">` at all, so phone browsers rendered it at desktop width (~980px) and scaled everything down — tiny text, wrong card width. Added `width=device-width, initial-scale=1, viewport-fit=cover`. This only ever showed up on a real phone; desktop testing never caught it.
- **Mobile drag-vs-native-scroll conflict fixed** (round 3): see the new contract entry above (`touch-action:none` on `.stack-wrap` + html/body scroll lock). Symptom was "the whole screen moves, the card won't drag" on a real phone; worked fine on mouse/trackpad the whole time.
- **Drag-release animation switched to a spring/overshoot curve** (round 3): see the new contract entry above. User feedback was that the release snap "doesn't feel natural" / "too fast" even after a first attempt at just slowing it down — the real fix was the easing curve shape, not the duration.
- **In-app reload button added** (round 3, top-right of the home reel): installed as a standalone home-screen app, there's no browser chrome at all — no address bar, no pull-to-refresh, no way to get a fresh copy short of force-quitting and reopening. The button does a cache-busted `location.replace()` so the user can grab the latest published version without leaving the app.

### DONE (round 1)
- Locked-card corner-radius clipping bug (Chromium `overflow:hidden`+`border-radius`+`filter`+`preserve-3d` interaction) — fixed with `clip-path`.
- Shadow-smear "blob" bug when the deck gathers — fixed with a box-shadow-only fade, separate from the transform/opacity transitions.
- "IN PROGRESS" pill flashing to its real color right at the end of the close animation — the transient closing element was missing the `active` status class that real deck cards get; fixed by matching classes exactly.
- Deck-spread race condition — the final DOM swap was on a fixed timer that assumed (with only ~40ms margin) the deck's spread-out transition had already finished; under any real jank it could fire early and snap the deck. Fixed by waiting on the actual `transitionend` event instead of a guessed delay.
- Subpixel "shimmer" across the whole card at the end of closing — caused by destroying the just-landed animated element and rebuilding it from scratch via `render()`. Fixed by folding the same DOM element into the deck permanently instead of replacing it.
- Day 2 given a real photo (user's own, embedded as base64 JPEG) instead of the generated gradient placeholder.
- PWA installability: `manifest.json`, `icon-512.png`, and the associated meta/link tags.
- Outer demo/gallery chrome (stagehead, filmrail, phone bezel) stripped so the page is the app, full-bleed.
- Project moved into version control: GitHub repo created at github.com/everydayou/japan-slowly, pushed with `index.html`, `manifest.json`, `icon-512.png`, `README.md`, `PROJECT-CONTEXT.txt`, `CHANGELOG.txt`, and the two source `.docx` planning documents under `docs/`.

## Recent Rounds (most recent shown; full history in CHANGELOG.txt)
### ROUND 3 — Live on GitHub Pages, real-device mobile fixes (2026-09-15)
Turned on GitHub Pages so the app is actually reachable and installable on a phone (`https://everydayou.github.io/japan-slowly/`). Testing on a real device (as opposed to desktop browser / Playwright emulation, which had been the only verification method through round 2) surfaced three genuine bugs that never showed up any other way: no viewport meta tag at all (phone browsers rendered at desktop width and scaled everything down), `.stack-wrap`'s `touch-action:pan-y` letting the browser's native vertical-scroll gesture hijack the horizontal drag-to-browse gesture on any real (non-perfectly-horizontal) finger drag, and `html`/`body` having no scroll lock at all so the whole document could pan/bounce in both directions on top of that. Fixed all three (viewport meta tag; `touch-action:none` + full html/body scroll lock with `overscroll-behavior`; `.view` given `overscroll-behavior:contain` so its own legitimate internal scroll doesn't chain up into a body-level bounce). Separately, reworked the drag-release snap animation from a front-loaded ease-out to a gentle spring/overshoot curve per user feedback that it "didn't feel natural" — the real issue was curve shape, not duration (a first attempt at just slowing it down wasn't perceptibly different). Added an in-app reload button (top-right of the home reel) so the user can force-fetch the latest published version without needing browser chrome, which a standalone installed home-screen app doesn't have. All changes verified with Playwright (including iPhone touch/viewport emulation) before handoff; user pushed each change from their own machine, including switching to a Personal Access Token for git auth on a second (new) computer partway through the round.
